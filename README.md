# 移动式多参数环境监测系统 (DC-MEMS)

基于 STM32 与 ESP32 双核架构的移动式环境监测小车，大二上持续更新的项目。

一开始只是想做个小车，后来觉得光跑太单调，就加了环境传感器；再后来发现数据只能在 OLED 上看太局限，又加了 ESP32 准备搞 WiFi 上云。慢慢就缝合成现在这个样子了。

## 硬件大概配置

- STM32F103C8T6：主控，管电机、避障、读传感器
- ESP32 裸板：负责联网和蓝牙
- TB6612 + 4个直流减速电机：差速转向
- HC-SR04：超声波避障
- SHT30：温湿度
- BH1750：光照
- ENS160 + AHT20：空气质量（AHT20 负责给 ENS160 做温湿度补偿）
- 0.96寸 OLED + 蜂鸣器：本地显示与报警

## 软件与引脚分配

STM32 负责干累活（实时控制、避障、传感器），ESP32 负责干轻活（通信）。

传感器全挂在 STM32 手写的软件 I2C 上（PB6/PB7），地址一锅端：
- OLED：0x78
- SHT30：0x44
- BH1750：0x23
- ENS160：0x53
- AHT20：0x38

其他引脚：
- 电机 PWM：PA2/PA3 (TIM2_CH3/4)
- 电机方向：PA4~PA7
- 超声波 Trig/Echo：PB12/PB13 (TIM4 测距)
- 蜂鸣器：PB11
- 预留 ESP32 串口：PA9/PA10 (USART1)

主循环的调度逻辑是：静止的时候采环境数据（因为没有电机干扰），移动的时候专心避障。

## 踩过的坑与记录

**1. 为什么不用硬件 I2C？**
F103 的硬件 I2C 有死锁 Bug，小车电机干扰大，动不动就卡死。直接手写了软件 I2C，虽然慢点，但稳。以后遇到任何 I2C 设备都能直接套用。

**2. BH1750 读数不对**
一开始想算百分比，用 raw / 65535 * 100，结果手电筒照着也就百分之几。后来翻数据手册才发现，高分辨率模式下 `Lux = raw / 1.2`，直接显示 Lux 才对。

**3. 引脚冲突**
超声波 Trig 一开始也想接 PB0，结果和 I2C 的 SCL 冲突了。后来把 I2C 全部改到 PB6/PB7。这件事让我学乖了，把所有引脚都写成宏定义重映射，以后改线只改头文件就行。

**4. 蜂鸣器导致 OLED 变暗**
蜂鸣器响的时候，屏幕会暗一下。查了一下是电机或者大电流负载瞬间抢电，导致系统电压跌落。后面在蜂鸣器供电端并了个 100μF 电容，同时把引脚从冲突的 PB8 改到了 PB11。

**5. 超声波分压**
HC-SR04 的 Echo 输出 5V，绝对不能直接接 STM32 的 IO，一定要用 1k 和 2k 电阻分压到 3.3V。这种物理层面的坑，代码写得再好也救不回来。

**6. 避障逻辑的物理局限**
现在用的是“后退 + 原地旋转扫描”的逻辑。但在实测中发现，超声波波束角只有 15 度，探头探测到 50cm 的缝隙，车身未必能顺利通过。目前先把安全阈值提到 80cm，暂时够用。后续如果升级，考虑车头呈“八”字形布置双超声波，更智能。
