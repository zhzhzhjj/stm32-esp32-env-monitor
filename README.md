# 移动式多参数环境监测小车

STM32 + ESP32 的一个双核小车，大二上准备一直搞的项目。

最开始就是想做个蓝牙遥控车，后来觉得太水了，就加了点传感器进去测环境。再后来发现只能在OLED上看数据太蠢，就又加了个ESP32搞WiFi上云。搞着搞着就变成现在这个四不像了。

硬件大概就是这些：
STM32F103C8T6当主控，管电机和传感器。
ESP32专门负责上网和蓝牙。
电机驱动是TB6612，四个直流减速电机。
传感器有点多，超声波HC-SR04用来避障，SHT30测温湿度，BH1750测光照，ENS160+AHT20测空气质量。还有一个OLED和一个蜂鸣器。

大概的思路就是，STM32干累活（实时控制、避障、读传感器），ESP32干轻活（联网）。两个芯片用串口互相传数据。

传感器全挂在STM32手写的软件I2C上。地址分别是：OLED（0x78）、SHT30（0x44）、BH1750（0x23）、ENS160（0x53）、AHT20（0x38）。一锅端，全都接在PB6和PB7上。

主循环逻辑是：车停下来的时候去采环境数据，车一动就只管避障。因为电机一转，ADC和传感器的数据就疯狂乱跳，这个坑我调了好久才想通。

踩过的一些坑：
1. 为什么不用硬件I2C？因为F103的硬件I2C有死锁Bug，加上小车电机干扰大，动不动就卡死。我直接用GPIO手写了软件I2C，保证稳定最重要
2. BH1750一开始读数不对。我把它算成了百分比，用raw除以65535再乘100，结果手电筒照着也就百分之几。后来翻数据手册才发现，高分辨率模式下Lux就等于raw除以1.2，直接显示Lux就对了。
3. 引脚冲突。超声波Trig要用PB0，我I2C一开始也用了PB0，直接打架。后来把I2C改到PB6和PB7了。这事让我学乖了，把所有引脚都用宏定义重映射，以后改线只改头文件就行。
4. 面包板坑死人。杜邦线内部断过，面包板簧片松过，我排查了半天代码，最后发现是线的问题。后面准备把电源和信号线焊到洞洞板上，不想再碰面包板了。
5. SHT30的驱动比BH1750要复杂点，它带CRC-8校验。一开始没写校验，偶尔读到八十多的温度这种离谱数据。另外OLED的ShowNum函数不能直接显示浮点数，得先乘以10转成整数，再拆开显示小数位。

后面打算把传感器数据打包成帧发给ESP32，大概是0xAA加数据加校验加0x55这种格式。然后ESP32用PubSubClient推到MQTT服务器。手机端还没想好用啥，可能先搞个MQTT调试APP顶着。
